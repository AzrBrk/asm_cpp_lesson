**小任务分析与解答**

设某函数刚进入时 `rsp = 4088`，随后执行 `pushq %rbx`（保存 rbx；rsp 减少 8，并写入这 8 字节）。

它接下来要调用另一个无参数函数。只考虑 shadow space 和调用前对齐：

### 1. `pushq` 后 `rsp` 是多少？是否 16 字节对齐？
*   **计算**：`4088 - 8 = 4080`
*   **取模**：`4080 % 16 = 0`
*   **结论**：此时 `rsp = 4080`，**与 16 字节对齐**。

### 2. 此时再减 32，执行 `call` 前是否同时满足空间大小和对齐要求？
*   **计算**：`4080 - 32 = 4048`
*   **取模**：`4048 % 16 = 0`
*   **结论**：此时 `rsp = 4048`，**与 16 字节对齐**。`shadow space` 的空间大小是 32 字节，满足分配空间大小需求，同时也满足对齐要求。

### 3. 此时再减 40，执行 `call` 前是否对齐？写出余数。
*   **计算**：`4048 - 40 = 4008`
*   **取模**：`4008 % 16 = 8`
*   **结论**：此时 `rsp = 4008`，**与 16 字节不对齐**，余数为 **8**。

*(注：若在此状态下直接执行 `call`，将违反 x64 调用约定。因为 `call` 会压入 8 字节返回地址，进入被调函数后 `rsp` 将变为 4000)*

```
rsp = 4088
pushq %rbx            # rsp - 8 = 4080
```

1. rbx占用4080 - 4087

```
subq $32, %rsp # 预留下一次调用的 shadow space，rsp = 4048
```

2. 下一次调用的shadow space 占用 4048 - 4079

3. 下一次函数刚进入是，由于call，rsp 减8， 所以入口是 4040， 返回地址占 4040 - 4047

4. 保存的rbx占用4080 - 4087， 不在这次调用的shadow space里，不能被对方当作home slot覆盖
