# 内联汇编的 UB 边界 — 契约、未指定、真 UB

> 这一节不属于某一课，是横着切的：**判断一个 asm 问题是"编译器报错""我违约了"还是
> "C++ 层面的 UB"**。写 context switch 之前，这张分类表比多背十条指令有用。
>
> 触发原因：`progress.md` 的易错点里有"同一变量同时出现在 `"=r"(x)` 和 `"r"(x)` 里，
> 行为不确定"。这类条目如果不分类，就会被误当成"跑通了就没事"。

---

## 0. 先把"UB"这个词拆开

日常说"这是 UB"，其实混了四种完全不同的东西：

| 层 | 是什么 | 谁定义 | 违反了会怎样 |
|---|---|---|---|
| **L0 硬错误** | 语法/约束/汇编/链接错误 | GCC、GAS、链接器 | 编译不过，最安全 |
| **L1 契约** | GCC 文档对 asm 的硬性要求 | GCC 手册 | 编译器可以按"你没违约"来优化 → 静默错码 |
| **L2 未指定** | GCC 没承诺具体行为 | 无 | 这次能用，换版本/换分配就变 |
| **L3 真 UB** | C++ 抽象机层面的 UB | C++ 标准 | 整个程序的行为都失去保证 |

**只有 L1 和 L3 叫"UB"是合适的**；L2 应该叫"别依赖"。L0 连 UB 都不是。

---

## 1. L0：编译器直接拦你（不是 UB）

| 写法 | 报错 |
|---|---|
| `"i"(运行期变量)` | `impossible constraint in 'asm'` |
| `"K"(0xFF)` | `impossible constraint in 'asm'` |
| `::: "x"` | `unknown register name 'x' in 'asm'` |
| 当前函数将 `rbp` 用作帧指针时再 clobber 它 | `bp cannot be used in 'asm' here`（不是所有上下文都报） |
| `andq %eax, %rdx` | `incorrect register '%eax' used with 'q' suffix` |
| 模板两条指令之间没 `\n` | `junk 'addq %rsi' after register` |

这一层是礼物：**报错越早越便宜**。所以约束能写窄就别写宽。

---

## 2. L1：GCC 文档规定的契约（违反 = asm 未定义）

| 契约 | 文档依据 | 违反的症状 | 正确写法 |
|---|---|---|---|
| **输出必须被写** | Output Operands：编译器不检查，假定你写了 | 返回值是寄存器里的垃圾 | 每条输出都真的写；或别声明它 |
| **输入只读** | Input Operands | 你改的可能是 C 变量本身，编译器不知道 | 要改就 `"+r"`；草稿用 `"=&r"` 新输出 |
| **clobber 完整** | Clobbers | 编译器继续用被擦掉的寄存器/内存/flags | Lesson 2 的表 |
| **`rsp` 前后一致** | Clobbers：stack pointer 必须相同 | 所有 `"m"` 操作数、spill 槽全错位 | 换栈用 naked / `.S` |
| **先写输出要用 `&`** | Constraint Modifiers | 输出吃掉还没读的输入 | Lesson 1 §2 |
| **`"memory"` 覆盖隐藏访存** | Clobbers | load 被 CSE/搬过 asm | Lesson 2 §2 |
| **callee-saved 要恢复** | ABI（不是 asm 文档） | 调用者的变量被静默改掉 | push/pop 或 clobber |
| **栈对齐 16** | ABI | `movaps` 崩 | Lesson 3 §4 |
| **`asm goto` 输出每路径都写** | Goto Labels | 未定义值 | 全写或 `+` |

判断方法：**这条要求能不能在 GCC 手册里找到原话？** 能找到 → L1；找不到 → 往下看。

---

## 3. L2：GCC 没承诺的"未指定行为"（别依赖）

| 场景 | 实际会发生什么 | 为什么不能依赖 |
|---|---|---|
| 同一变量既做输出又做输入 | 操作数可同寄存器也可不同；旧值输入与新值输出本身合法 | 不能从 C 变量相同推出操作数绑定 |
| `"r"` 具体选哪个寄存器 | 任意空闲 GPR | 换一行代码就变 |
| `"g"` 选 r / m / i | 看上下文 | 模板要能吃三种形态 |
| 非 volatile 且输出没人用 | 整块删除 | 优化器自由 |
| 非 volatile 且被内联两次 | 可能复制成两份 | 优化器自由 |
| 代码长度/编码选择 | GAS 决定最短形式 | 别写死字节数 |

**L2 的可怕之处**：它今天"能用"。你写 100 个测试全过，换台机器就错。
处理原则：**只要手册没写，就当成"我欠了一个保证"** —— 要么改用 L1 的写法，要么加断言。

---

## 4. L3：C++ 层面的 UB（asm 不豁免）

| 场景 | 为什么是 UB | 和 asm 的关系 |
|---|---|---|
| 两个线程无同步读写同一内存 | C++ 数据竞争 | `"memory"` 只是编译器屏障，不是同步 |
| 读未初始化变量 | 不确定值 | 作为 asm 输入也是 UB |
| 栈溢出/越界写 | 越界 | 切栈后更容易发生 |
| 用普通指针做类型双关 | 严格别名 | asm 里读写也不豁免 |
| 信号处理里调非 async-signal-safe 函数 | 标准 | 在 fiber 栈上收信号更容易踩 |

**关键**：`asm` 是编译器扩展，它**不能**把 C++ 的 UB 变成"有定义"。
你在 asm 里写 `movl $1, (%rax)`，如果 `%rax` 指向越界，照样是 UB。

## 5. 重点：同一个变量当输入和输出

这是你的清单里那条"行为不确定"。三种写法，实测（GCC 13.3，`-O2`）：

### 写法 A：`"=r"(x) : "r"(x)`，模板只引用 `%0`

```cpp
__asm__ volatile("addq $1, %0" : "=r"(x) : "r"(x));
return x;
```

`-S`：

```asm
#APP
	addq $1, %rax
#NO_APP
ret
```

结果：

```
same_var(10) = 542205718625     ← 不是 11
```

为什么：`%0` 是**只写**输出，GCC 不会把 `x` 预加载进去；`%1`（输入）在模板里没被引用，
GCC 也没有理由搬它。两个操作数被分到了不同寄存器（`%rax` 和 `%rdi`），
`addq $1, %rax` 加的是垃圾。**"同一个变量"不等于"同一个寄存器"。**

### 写法 B：模板两个都引用

```cpp
__asm__ volatile("movq %1, %0\n\taddq $1, %0" : "=r"(x) : "r"(x));
```

```asm
	movq %rdi, %rax
	addq $1, %rax
```

结果 11。**这种数据流是合法的**：不论是否同寄存器，第一条 mov 都把输入送到输出，
后面的 add 只改输出，不再读取原输入。还应显式声明 `"cc"`。
不保证的是具体寄存器，不是正确性；不能把它误判为违约。

### 写法 C：`"+r"`（唯一推荐）

```cpp
__asm__ volatile("addq $1, %0" : "+r"(x));
```

读写绑成一个操作数，天然同址，没有"两个操作数要不要合并"的问题。

### 结论

- 同一变量出现在两个操作数里：本身合法，但不是“自动同寄存器”；
  把只写输出当成已装入旧值，才是错误。
- 你想要"同址"，用 `"+r"` 或 `"=r"(out) : "0"(in)` 显式表达。
- 不同 C 变量也不保证不同寄存器；需要不重叠时用正确约束表达。
- 加上 `&` 与否，是另一个维度（Lesson 1 §2）。

## 6. 另外两个实测：输出不写、输入乱改

### 输出槽位没写

```cpp
uint64_t r;
__asm__ volatile("" : "=r"(r) : "r"(x));
return r;
```

```asm
unwritten:
	ret          # 整个 asm 没有指令
```

结果：

```
unwritten(10) = 39      ← 没有期望值，纯垃圾
```

GCC 不报错、不警告，因为它假定"输出操作数会被写"。**这是 L1 违约，不是 L2。**

### 改写 input-only 操作数

```cpp
__asm__ volatile("movq %1, %0\n\taddq $1, %1" : "=r"(r) : "r"(x));
return r + x;
```

```asm
	movq %rdi, %rax
	addq $1, %rdi      # 改的是 x 所在的寄存器
	addq %rdi, %rax
```

结果 21。按"输入只读"的语义，`x` 应该还是 10（`r + x = 20`）；
但 GCC 把 `x` 直接放在 `%rdi`，你改了它，**C 变量被静默改掉**，而编译器不知道。
这是 L1 违约的典型：不是立刻崩，是后面某个地方用旧值/新值不一致。

## 7. 怎么审查“这段 asm 没违约”

四步，缺一不可：

1. **查条款**：每个"我这么写没问题"的假设，在 GCC 手册里找得到原话吗？
2. **看 `-S`**：指令来自模板还是编译器？操作数是不是同一个寄存器？
3. **换条件**：`-O0/-O1/-O2/-O3`、`-fno-stack-protector`、换 clang，结果一致吗？
4. **在边界打断言**：输入输出前后各 assert 一次（Lesson 1 遗留账里那条）。

有限测试不是“没有 UB”的数学证明。必须先检查接口是否对**所有约束允许的分配**
都成立，再用测试找实现与推导的差异。不确定时标未验证，不伪造某个 UB 分类。

例如“多个输出”不自动要求全部加 `&`，应逐项查时序；“省略 cc”
也不能脱离目标后端下结论，见 Lesson 2 §3.4 的 GCC x86 隐式 flags clobber。
函数类型、ABI、C++ 对象有效性属于不同层，不能把任何未知行为都叫同一种 UB。

---

## 8. 写 asm 前的 8 个问题

1. 模板里引用了每个操作数吗？
2. 每条输出都真的写了吗？
3. 有没有"先写输出、后读输入"？→ `&`
4. 改了输入吗？→ 改 `"+r"` 或新输出
5. 动了哪些寄存器/内存/flags？→ clobber
6. 同一个 C 变量出现了两次吗？→ 能不能合并成 `"+r"`
7. asm 前后 `rsp` 一样吗？
8. 这段代码在 `-O0` 和 `-O2` 下都跑过吗？
