# Lesson 7 教案 — 首次进入

> **状态：已补 MS 帧、参数跳板和退出对齐，未开讲。**
> 前置：Lesson 6（栈切换）、Lesson 3（帧与对齐）。
> 本课目标：让一个**从没运行过**的函数"从 `ctx_switch` 里返回"那样开始执行，
> 并给它传参数。

---

## 开讲拆分

| 顺序 | 小任务 | 停点/证据 |
|---|---|---|
| 1 | 从 pop 顺序反推每个槽，不写初始化函数 | 提交偏移表；对照 `.S` 一项不漏 |
| 2 | 手算首次 ret 前后 `rsp` | 同时核对余数与可用内存范围，不只看对齐 |
| 3 | 给入口传一个指针/整数 | MS 用 trampoline 设 `rcx`；检查入口真实寄存器 |
| 4 | 让入口正常返回，再回主栈 | 退出处正确对齐并调用完成路径；主栈回收，禁止恢复 DEAD |

这一课的布局必须与**自己的切换原语**一致。下面 8 槽图只解释历史 GPR demo，
加了 XMM/控制字的 Windows 实现必须重新推导，不能把常量 80 照抄过去。

---

## 0. 问题：新栈上没有"上次"

`ctx_switch` 的工作是"返回到对方上次停下的地方"。可是新 fiber 从没调用过它 ——
它的栈顶是什么？返回地址在哪？

答案：**你伪造一个"刚被切走"的帧**，让 `ctx_switch` 以为它只是"上次被切走了"。

---

## 1. 假帧的布局：先读 SysV 的 GPR-only 示意

```
高地址
┌──────────────────────────┐ ← top（16 字节对齐）
│  fiber_exit（返回地址）   │ ← [top-8]   fiber 若 return 就落到这里
├──────────────────────────┤ ← [top-16]  ctx_switch 的 ret 目标
│  fiber 入口地址           │
├──────────────────────────┤
│  r15  r14  r13  r12       │  8 个「保存寄存器」槽位
│  rdi  rsi  rbx  rbp       │  （顺序和 push/pop 相反）
├──────────────────────────┤
└──────────────────────────┘ ← sp = top - 80
低地址
```

下面仅说明历史布局的局部槽位，不作为 Windows 初始化实现：

```cpp
uint64_t *top = stack + kStackWords;   // 栈顶为 one-past-end，必须 16 对齐
uint64_t *sp  = top - 10;              // 80 字节

sp[8] = (uint64_t)entry;               // ctx_switch 的 ret 目标
sp[9] = (uint64_t)fiber_exit;          // fiber 的返回地址

*slot = sp;
```

### 1.1 不看图猜：低地址到高地址的精确表

此表来自 `push rbp/rbx/rsi/rdi/r12/r13/r14/r15` 与逆向 pop：

| 相对保存指针 | 恢复去向 |
|---|---|
| `+0 / +8 / +16 / +24` | `r15 / r14 / r13 / r12` |
| `+32 / +40 / +48 / +56` | `rdi / rsi / rbx / rbp` |
| `+64` | 切换原语 ret 的目标 |
| `+72` | 直接进入入口时，入口自己的返回地址 |

“顺序相反”不够：必须能写出 `+32` 对应哪个寄存器。

---

## 2. 为什么是 `top - 10`、`top - 8`

一步一步算：

1. `top` 16 字节对齐（`alignas(16)` + 数组长度是 16 的倍数）。
2. `sp = top - 80`。
3. `ctx_switch` 从 `sp` 开始 `pop` 8 个寄存器 → `rsp = top - 16`。
4. `ret` 弹出 `[top-16]` 的入口地址 → `rsp = top - 8`。
5. 入口函数看到 `rsp = top - 8`，即 `(top - 8) % 16 == 8` —— **正好是函数入口的约定**。

第 5 步是全部意义所在：C 函数一进门就假设 `rsp % 16 == 8`，
它的序言据此把栈再对齐到 0 去 `call` 别人。差 8 字节，`movaps` 就会崩。

### 2.1 MS x64：对齐之外还欠 32 字节

设新普通 C++ 入口的 `rsp=E`，必须同时有：

- `E % 16 == 8`；
- `[E,E+7]` 是其返回地址；
- `[E+8,E+39]` 是调用方为它留下的 32 字节 home slots，必须在已分配栈内。

旧图 `E=top-8`，则 home slots 落在 `[top,top+31]`，**越过数组末尾**。
“demo 只打印整数”不能豁免这个要求。
仅为说明缺口，仍用 8 槽 GPR-only 模型，令 `E=top-40`：

| 内容 | 地址 |
|---|---|
| 入口 home slots | `top-32 … top-1` |
| 入口返回地址 | `top-40` |
| 首次切换 ret 目标 | `top-48` |
| 8 个 GPR 槽起点 | `top-112` |

`sp+64=top-48`，再 ret 后 `rsp=top-40`，余数和边界都成立。
**112 也不是最终 Windows 帧尺寸**：完整保存区应含 XMM/控制字/平台字段，
并按它们的对齐要求重算。主线推荐先进入 trampoline，再由它分配出站 shadow space、
用普通 `call` 启动用户函数，避免把所有责任塞进一个假返回地址。

## 3. 传参数：往"保存槽"里塞

`ctx_switch` 的 `pop` 顺序是 `r15 r14 r13 r12 rdi rsi rbx rbp`，
所以 `rdi` 槽位（`sp[4]`）里放什么，入口函数就"收到"什么：

```cpp
sp[4] = 12345;                        // 入口函数的第一个参数
sp[8] = (uint64_t)&fiber_arg;
```

实测：

```
fiber 收到参数: 12345
```

这不是魔法：`popq %rdi` 把 12345 装进了 `rdi`，紧接着 `ret` 跳到
`fiber_arg`，而 SysV 的第一个参数正好在 `rdi`。
**Windows 不能这样换个槽号就完成**：当前 8 槽序列根本没有 `rcx`，
因为它是易失参数寄存器。建议在已保存的非易失寄存器槽中携带入口地址与 `arg`，
恢复后跳到汇编 trampoline，由它把 `arg` 搬进 `rcx`，按 MS ABI 调用用户入口。
不要要求 `ctx_switch` 普通返回时保留原来的 `rcx`。

参数类型要一致，例如约定用户入口为 `void (*)(void*)`，上下文里传递 `void*`。
模板修饰符不会完成类型转换；函数指针、整数槽的互换属于目标平台扩展，
不是可移植 ISO C++。

---

## 4. 退出路径

在旧图中，fiber 函数返回会 ret 到 `sp[9]` 的 `fiber_exit`，但还有一笔对齐债：
入口 `rsp=E` 为 8 mod 16，入口返回后 `rsp=E+8` 为 **0 mod 16**。
直接落入另一个普通 C++ `fiber_exit` 不满足它的入口约定；
Windows 的 home slots 也不能凭空继承。
所以一个完整的 fiber 生命周期是：

```
伪造帧 → 汇编 trampoline → 按 ABI call 用户入口 → 正常 return 到 trampoline
→ 按 ABI call 不返回的完成路径 → 切回调度栈 → 回收
```

完成路径标记 DEAD，再切回调度器，约定永不恢复。若意外恢复到这里应显式陷阱/终止，
不是再 ret 读取未初始化地址。它的栈随后可以释放/复用 ——
但**不要在它自己的栈上释放**，因为那行代码还在用它。

> 本课程的 demo 里 fiber 都是死循环，`fiber_exit` 只是保险。真要支持"fiber 结束"，
> 这里要加一层"回收栈"的机制。

---

## 5. `ret` 还是 `jmp`：boost 的选择

我们的 `ctx_switch` 用 `ret` 跳到对方。boost 的 `jump_fcontext` 用的是：

```asm
movq 0x40(%rsp), %r8    # 取出对方的返回地址
...
leaq 0x48(%rsp), %rsp   # 把栈恢复到"函数返回后"的样子
jmp  *%r8               # 直接跳，不用 ret
```

这一段是 **SysV 源码的形状示意**，不是 MS 版偏移。CET 解释了为什么不能随便用 ret：

- `ret` 会同时弹普通栈和影子栈；如果你只是 `movq %rsp` 换了普通栈，
  影子栈没换，`ret` 会因两者不匹配而触发 `#CP`；
- 但只改为 `jmp` **不构成 CET 支持**；未来的普通 ret 仍需要匹配影子栈。
  启用对应分支的实现还会恢复 SSP、调整影子栈深度，并处理间接分支要求。

`jmp` 本身也不弹普通栈；必须先模拟 ret 的读取和 `rsp` 推进。
是否支持 CET 要看具体平台、版本、宏与 OS 配置，不能从一个 `jmp` 下结论。
**这是"为什么工业代码比 demo 长"的第一个原因。**

---

## 6. `make_fcontext` 就是干这个的

boost 的 `make_fcontext(stack_top, stack_size, fn)` 返回一个 `fcontext_t`，
内部做的正是本课的假帧构造：

1. 从栈顶往下留出保存区；
2. 写入入口 trampoline 的地址；
3. 写入 `fn` 作为"入口函数的参数"（它用一个 trampoline 把 `fn` 转成调用）；
4. 返回新的栈顶指针。

差别在于它还处理了对齐、CET、以及"第一次进入时把 `fn` 当参数传进去"的细节。
Lesson 9 会逐行对。

## 7. 任务

### 任务 A：给 fiber 传参

把 demo 改成 `fiber_a(long id)` / `fiber_b(long id)`，通过保存槽传不同的 id，
主线先用 `void*` 传两个不同对象，由入口检查对象字段。要求：
标出保存槽→trampoline 寄存器→`rcx`→C++ 参数的完整路径，
并在调试器核对入口值。SysV 直接槽传参为对照，不要求两平台同时完成。

### 任务 B：实现 `fiber_exit`

让 fiber 函数正常 `return`（不是死循环），由 `fiber_exit` 切回 main。
要求：每个入口恰好完成一次；入口 call 前与完成路径 call 前对齐正确；
由主栈记录完成并回收，打印本身不是 ABI 证明。

### 任务 C：对齐实验

独立坏版本：在正确的本平台布局上故意偏移 8 字节，观察：

- 纯整数的 fiber 是否还正常？
- 加一个 `printf("%f")` 的 fiber 会不会崩？
- 用 `gdb` 看崩在哪条指令（大概率是 `movaps`）。

### 任务 D：`jmp` 版

把 `ctx_switch` 的最后一条 `ret` 换成"先取返回地址到 `%r8`，恢复 `rsp`，再 `jmp *%r8`"。
对比两种写法的 `-S`/`objdump`，说明两者的栈效果。此任务只比较普通控制流，不以它宣称实现了 CET。

## 8. 易错点

1. 初始 `sp` 算错 8 字节（`movaps` 崩）。
2. 假帧里寄存器槽顺序和 `pop` 顺序不一致（参数/寄存器全错）。
3. 忘了写"fiber 的返回地址"，函数一 `return` 就跳到 0。
4. 在 `fiber_exit` 里释放自己正在用的栈。
5. 以为 `ret` 一定安全（CET 下不是）。
6. 参数槽位按 SysV 写，拿到 Windows 上用（`rdi` vs `rcx`）。
7. 把“汇编遗留一个多余参数寄存器值”与“通过不兼容 C++ 函数指针调用”混为一谈；
   后者才是函数类型契约错误。统一入口类型，不靠碰巧忽略寄存器过关。
