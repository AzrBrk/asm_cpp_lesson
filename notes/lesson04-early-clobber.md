# Lesson 4 教案 — Early Clobber 与多输出

> **状态：已补时序分析与约束勘误，未开讲。**
> 前置：Lesson 1 [`deep-dive` §2](lesson01-deep-dive.md)（`&` 的基础）、Lesson 3（寄存器保存）。
> 本课目标：看到**一条 asm 里有两条以上指令、或两个以上输出**时，
> 能判断"哪个输出必须在第一条指令就写"，并知道用哪个约束字符表达。

---

## 开讲拆分：先分析时序，再写约束

| 顺序 | 小任务 | 验收证据 |
|---|---|---|
| 1 | 把一个两指令模板的每个读写列出来 | 每个输出第一次写入、每个未绑定输入最后读取的位置 |
| 2 | 对两个输出分别判断 `&` | 危险重叠示意 + 实际 `-S`；不强求坏版必错 |
| 3 | 固定寄存器输入输出绑定 | 用 `cpuid` 解释 `+a/+c` 或匹配约束，区分 ISA 固定位置与 early clobber |
| 4 | 申请草稿输出而非硬编码寄存器 | `-S` 比较实际保存/恢复指令数；可能没有减少，也要如实说明 |

`asm goto` 是选读，不是调度器前置。本文机器码示例来自历史 SysV 环境；
新练习统一使用 `std::uint64_t` / `std::int64_t`，不以 Windows 上 32 位的 `long` 配 `q`。

---

## 0. 问题的来源：一条假设

GCC 对一条 asm 有一个隐含假设（文档原话）：

> the assembler code consumes its inputs before producing outputs

**"先把输入读完，再写输出。"** 单指令模板基本成立；多指令模板经常不成立。

Lesson 1 的 `&` 解决的是"一个输出 + 多个输入"的情况。这一课补剩下的：

1. **多个输出**互相之间、以及输出和输入之间怎么排；
2. **固定寄存器输出**（`a`/`d`/`b`/`c`）和输入的绑定；
3. 什么时候该用 `&`、什么时候该用数字匹配 `"0"`/`"1"`；
4. 为什么"借一个固定寄存器当草稿"是坏习惯。

---

## 1. 多输出：`&` 不是可选项（实测）

```cpp
std::uint64_t a, b; // x 同为 uint64_t，避免 Windows 的 32 位 long 与 q 后缀冲突
__asm__ volatile("movq $0, %0\n\t"     // 先写 a
                 "movq $0, %1\n\t"     // 再写 b
                 "addq %2, %0"         // 最后才读输入
                 : "=r"(a), "=r"(b) : "r"(x) : "cc"); // 故意只漏 &，不混入漏 flags 声明
```

`-O2` 下 GCC 把输入 `x` 放在了 `%rdi`，输出 `a` 也分到了 `%rdi`：

```asm
	movq $0, %rdi        # a 和输入 x 同址 → x 被清零
	movq $0, %rax        # b
	addq %rdi, %rdi      # 0 + 0
```

运行：

```
no_amp(7)   = 0      ← 期望 7
with_amp(7) = 7      ← 两个输出都加 &
```

加上 `&` 之后：

```asm
	movq $0, %rax        # a
	movq $0, %rdx        # b
	addq %rdi, %rax      # x 还在 %rdi
```

**规则**：逐个输出判断，若它会在某个未绑定输入最后一次读取前被写，就要 `&`。
本例两个输出都提前写，所以都要；**不是只要多输出就全部加**。
此外要检查内存操作数的地址寄存器是否在输出写入后还会用。

| 步骤 | 写入 | 后面仍需读取的输入 | 本例结论 |
|---|---|---|---|
| `movq $0,%0` | `a` | `x` | `a` 要 `&` |
| `movq $0,%1` | `b` | `x` | `b` 要 `&` |
| `addq %2,%0` | `a`、flags | 当前读取 `x` | flags 用 `"cc"`，不靠 `&` |

## 2. 固定寄存器输出：`a` / `b` / `c` / `d`

x86 有些指令把结果写死在特定寄存器里：

| 指令 | 输出 | 输入 |
|---|---|---|
| `rdtsc` | `edx:eax` | 无 |
| `cpuid` | `eax/ebx/ecx/edx` | `eax`、`ecx` |
| `mul r/m` | `rdx:rax` | `rax`、操作数 |
| `div r/m` | `rax`（商）、`rdx`（余） | `rdx:rax`、操作数 |

写法就是把输出钉到对应字母：

```cpp
struct Cpu { unsigned a, b, c, d; };
Cpu cpuid(unsigned leaf) { // 固定寄存器读取 leaf/subleaf；EBX 输出由编译器负责 ABI 保存
    Cpu r;
    __asm__("cpuid"
            : "=a"(r.a), "=b"(r.b), "=c"(r.c), "=d"(r.d)
            : "a"(leaf), "c"(0));
    return r;
}
```

`-S` 看到的是：

```asm
	movl %edi, %eax
	xorl %ecx, %ecx
#APP
	cpuid
#NO_APP
```

这里**不用 `&`**：`cpuid` 先把 `eax/ecx` 读完，最后才写四个输出，正好符合那条假设。

但换成 `div` 就未必了：`cqto`（把 `rax` 符号扩展到 `rdx:rax`）是**模板第一条指令就写 `rdx`**。
如果分配器把除数放进了 `rdx`，`cqto` 会先把它清掉。这类"输出在输入读完之前就写"的情况，
就是 `&` 的用武之地。

> 判断方法：**在模板里找"第一条写输出的指令"和"最后一条读输入的指令"，看谁先。**
> 写在前 → 加 `&`。

## 3. `"A"`：i386 的遗产，x86-64 的坑

`"A"` 在 **i386** 上表示 `edx:eax` 这一对（`rdtsc`、64 位乘法的经典写法）。
x86-64 上不能用它表达一个 64 位变量占 `edx:eax` 两半，GCC 文档明确说：

> This is not correct on x86-64 as it would allocate tick in either ax or dx.

Lesson 2 §4.4 有实测：`"=A"` 读 `rdtsc`，高 32 位恒为 0，时间戳上半截静默丢失。

**教训**：`"A"` 只在 32 位代码里用；64 位下用两个 `"=a"`/`"=d"` 输出。

---

## 4. 数字匹配 `"0"` / `"1"`：让输入和输出同址

多输出仍可以用 `+`。若输入和输出使用不同 C 对象，可用数字匹配：
`"0"` 表示“和第 0 个输出操作数同一个位置”。

```cpp
// 局部片段：n/d/q/r 均为 int64_t；d!=0，且排除 INT64_MIN/-1
// cqto 提前写 rdx，所以余数输出需要 early clobber
std::int64_t q, r;
__asm__("cqto\n\tidivq %3"
        : "=a"(q), "=&d"(r)
        : "0"(n), "r"(d)
        : "cc");
```

实测 `-S`（`d` 被分到 `%rsi`）：

```asm
	movq %rdi, %rax
#APP
	cqto
	idivq %rsi
#NO_APP
```

三个要点：

1. `"0"(n)` 绑定 `"=a"(q)`；也可以先用 `q=n` 再用 `"+a"(q)`。
2. 顺序不能反：`idiv` 要求被除数在 `rdx:rax`，所以 `cqto` 必须在 `idiv` 前面。
3. 这类指令的"输入输出同址"是 **ISA 的硬要求**，不是优化 —— 数字匹配就是为它存在的。

`mul` 同理：

```cpp
std::uint64_t lo, hi;
__asm__("mulq %3" : "=a"(lo), "=d"(hi) : "0"(a), "r"(b) : "cc"); // 单条 mul，输出不提前写
```

**判据**：只要一条指令的输入寄存器同时是输出寄存器，就必须用数字匹配（或 `+`），
不能指望分配器“碰巧”放对。固定的 `"a"` 输入/输出也已强制同一物理位置，
不是没写数字就一定错；数字匹配更直接表达这条依赖。

## 5. 别拿固定寄存器当草稿纸

一个坏习惯：模板里 `movq $0, %%rbx` 临时清零，然后 `::: "rbx"`。
它能跑，但可能要求函数级保存/恢复（通常不是循环每轮一对，实际看 `-S`）。

正解是向编译器**再要一个输出**，让它自己挑寄存器：

```cpp
uint64_t tmp;
__asm__("movq $0, %0\n\taddq %1, %0"
        : "=&r"(tmp), "+r"(x)      // tmp 是草稿，x 是真正的输出
        :
        : "cc");
```

- `"=&r"(tmp)`：early clobber，保证 `tmp` 不会和输入撞；
- 编译器会挑一个空闲的 caller-saved 寄存器，不需要你写 clobber；
- 这就是 GCC 文档说的 "use early-clobber outputs instead of clobbers"。

## 6. `asm goto`：asm 里的分支

`asm` 可以跳到 C 标签：

```cpp
int is_zero(std::int64_t x) {
    __asm__ goto("testq %0, %0\n\tjz %l[zero]" : : "r"(x) : "cc" : zero); // 标签进入控制流图
    return 1;
zero:
    return 0;
}
```

`-S`：

```asm
#APP
	testq %rdi, %rdi
	jz .L3
#NO_APP
	movl $1, %eax
	ret
.L3:
	xorl %eax, %eax
	ret
```

三条规则（GCC 文档 *Goto Labels*）：

1. 推荐 `%l[name]`；数字编号还要把 `+` 输出的隐含输入算进去，不能只数列表项；
2. `asm goto` **永远隐式 volatile**（它控制不了自己会不会被执行）；
3. GCC 13 支持输出；应保证每条消费路径上的值有效。用 `+` 保留未写路径的原值，
   或在所有会消费它的路径上定义输出；仅仅把 `=` 改成 `+` 并不能修复其他数据流错误。

最小协作式调度器不需要它；无锁队列涉及额外并发语义，不在本课范围内。

## 8. 易错点

1. 多输出只给第一个加 `&`。
2. 以为 `"+r"` 能同时解决"多输出同址"。
3. 在 x86-64 上用 `"A"`。
4. `div`/`mul` 不用数字匹配，指望分配器猜。
5. 用固定寄存器当草稿，然后抱怨多出 `push`/`pop`。
6. `asm goto` 里跨路径没写输出。
7. 以为固定寄存器不能用 `&`；`"=&d"` 正是上述除法的必要描述。
   报约束冲突应检查是否又强迫未绑定输入占同一寄存器。
