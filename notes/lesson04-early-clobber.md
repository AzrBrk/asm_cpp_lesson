# Lesson 4 教案 — Early Clobber 与多输出

> **状态：教案 v1，未开讲。**
> 前置：Lesson 1 [`deep-dive` §2](lesson01-deep-dive.md)（`&` 的基础）、Lesson 3（寄存器保存）。
> 本课目标：看到**一条 asm 里有两条以上指令、或两个以上输出**时，
> 能判断"哪个输出必须在第一条指令就写"，并知道用哪个约束字符表达。

---

## 0. 问题的来源：一条假设

GCC 对一条 asm 有一个隐含假设（文档原话）：

> the assembler code consumes its inputs before producing outputs

**"先把输入读完，再写输出。"** 单指令模板基本成立；多指令模板经常不成立。

Lesson 1 的 `&` 解决的是"一个输出 + 多个输入"的情况。这一课补剩下的：

1. **多个输出**互相之间、以及输出和输入之间怎么排；
2. **固定寄存器输出**（`a`/`d`/`b`/`c`）和输入的绑定；
3. 什么时候该用 `&`、什么时候该用数字匹配 `"0"`/`"1"`；
4. 为什么"借一个固定寄存器当草稿"是坏习惯。

---

## 1. 多输出：`&` 不是可选项（实测）

```cpp
long a, b;
__asm__ volatile("movq $0, %0\n\t"     // 先写 a
                 "movq $0, %1\n\t"     // 再写 b
                 "addq %2, %0"         // 最后才读输入
                 : "=r"(a), "=r"(b) : "r"(x));
```

`-O2` 下 GCC 把输入 `x` 放在了 `%rdi`，输出 `a` 也分到了 `%rdi`：

```asm
	movq $0, %rdi        # a 和输入 x 同址 → x 被清零
	movq $0, %rax        # b
	addq %rdi, %rdi      # 0 + 0
```

运行：

```
no_amp(7)   = 0      ← 期望 7
with_amp(7) = 7      ← 两个输出都加 &
```

加上 `&` 之后：

```asm
	movq $0, %rax        # a
	movq $0, %rdx        # b
	addq %rdi, %rax      # x 还在 %rdi
```

**规则**：只要模板里"写输出"出现在"读某个输入"之前，那个输出就必须 `&`。
多输出时，**每个**都加 —— 因为你不知道分配器会把哪个输入塞到哪个输出后面。

---

## 2. 固定寄存器输出：`a` / `b` / `c` / `d`

x86 有些指令把结果写死在特定寄存器里：

| 指令 | 输出 | 输入 |
|---|---|---|
| `rdtsc` | `edx:eax` | 无 |
| `cpuid` | `eax/ebx/ecx/edx` | `eax`、`ecx` |
| `mul r/m` | `rdx:rax` | `rax`、操作数 |
| `div r/m` | `rax`（商）、`rdx`（余） | `rdx:rax`、操作数 |

写法就是把输出钉到对应字母：

```cpp
struct Cpu { unsigned a, b, c, d; };
Cpu cpuid(unsigned leaf) {
    Cpu r;
    __asm__("cpuid"
            : "=a"(r.a), "=b"(r.b), "=c"(r.c), "=d"(r.d)
            : "a"(leaf), "c"(0));
    return r;
}
```

`-S` 看到的是：

```asm
	movl %edi, %eax
	xorl %ecx, %ecx
#APP
	cpuid
#NO_APP
```

这里**不用 `&`**：`cpuid` 先把 `eax/ecx` 读完，最后才写四个输出，正好符合那条假设。

但换成 `div` 就未必了：`cqto`（把 `rax` 符号扩展到 `rdx:rax`）是**模板第一条指令就写 `rdx`**。
如果分配器把除数放进了 `rdx`，`cqto` 会先把它清掉。这类"输出在输入读完之前就写"的情况，
就是 `&` 的用武之地。

> 判断方法：**在模板里找"第一条写输出的指令"和"最后一条读输入的指令"，看谁先。**
> 写在前 → 加 `&`。

## 3. `"A"`：i386 的遗产，x86-64 的坑

`"A"` 在 **i386** 上表示 `edx:eax` 这一对（`rdtsc`、64 位乘法的经典写法）。
x86-64 上没有这个寄存器类，GCC 文档明确说：

> This is not correct on x86-64 as it would allocate tick in either ax or dx.

Lesson 2 §4.4 有实测：`"=A"` 读 `rdtsc`，高 32 位恒为 0，时间戳上半截静默丢失。

**教训**：`"A"` 只在 32 位代码里用；64 位下用两个 `"=a"`/`"=d"` 输出。

---

## 4. 数字匹配 `"0"` / `"1"`：让输入和输出同址

多输出时，`"+r"` 的语法糖不够用了 —— 一个变量只能绑一个操作数。
这时用数字匹配：`"0"` 表示"和第 0 个操作数同一个位置"。

```cpp
// 商 q、余 r，输入 n 必须和输出 rax 同址
long q, r;
__asm__("cqto\n\tidivq %3"
        : "=a"(q), "=d"(r)
        : "a"(n), "r"(d)
        : "cc");
```

实测 `-S`（`d` 被分到 `%rsi`）：

```asm
	movq %rdi, %rax
#APP
	cqto
	idivq %rsi
#NO_APP
```

三个要点：

1. `"a"(n)` 和 `"=a"(q)` 是两个操作数，但都钉在 `rax` —— 编译器知道它们是同一个物理寄存器。
2. 顺序不能反：`idiv` 要求被除数在 `rdx:rax`，所以 `cqto` 必须在 `idiv` 前面。
3. 这类指令的"输入输出同址"是 **ISA 的硬要求**，不是优化 —— 数字匹配就是为它存在的。

`mul` 同理：

```cpp
unsigned long long lo, hi;
__asm__("mulq %3" : "=a"(lo), "=d"(hi) : "a"(a), "r"(b));
```

**判据**：只要一条指令的输入寄存器同时是输出寄存器，就必须用数字匹配（或 `+`），
不能指望分配器"碰巧"放对。

## 5. 别拿固定寄存器当草稿纸

一个坏习惯：模板里 `movq $0, %%rbx` 临时清零，然后 `::: "rbx"`。
它能跑，但代价是编译器每轮都 `push`/`pop`（Lesson 3 §5）。

正解是向编译器**再要一个输出**，让它自己挑寄存器：

```cpp
uint64_t tmp;
__asm__("movq $0, %0\n\taddq %1, %0"
        : "=&r"(tmp), "+r"(x)      // tmp 是草稿，x 是真正的输出
        :
        : "cc");
```

- `"=&r"(tmp)`：early clobber，保证 `tmp` 不会和输入撞；
- 编译器会挑一个空闲的 caller-saved 寄存器，不需要你写 clobber；
- 这就是 GCC 文档说的 "use early-clobber outputs instead of clobbers"。

## 6. `asm goto`：asm 里的分支

`asm` 可以跳到 C 标签：

```cpp
int is_zero(long x) {
    __asm__ goto("testq %0, %0\n\tjz %l[zero]" : : "r"(x) : : zero);
    return 1;
zero:
    return 0;
}
```

`-S`：

```asm
#APP
	testq %rdi, %rdi
	jz .L3
#NO_APP
	movl $1, %eax
	ret
.L3:
	xorl %eax, %eax
	ret
```

三条规则（GCC 文档 *Goto Labels*）：

1. `%l[name]` 引用标签；数字形式 `%l2` 的编号 = 输入输出操作数总数 + 标签序号；
2. `asm goto` **永远隐式 volatile**（它控制不了自己会不会被执行）；
3. GCC 13 **允许输出操作数**，但只在部分路径上写输出是危险的 —— 没写的路径上值未定义。
   要么所有路径都写，要么用 `+`。

`asm goto` 是后面写"最小调度器"时做快速路径的工具（比如无锁队列的"尝试一次，失败就跳走"）。

## 8. 易错点

1. 多输出只给第一个加 `&`。
2. 以为 `"+r"` 能同时解决"多输出同址"。
3. 在 x86-64 上用 `"A"`。
4. `div`/`mul` 不用数字匹配，指望分配器猜。
5. 用固定寄存器当草稿，然后抱怨多出 `push`/`pop`。
6. `asm goto` 里跨路径没写输出。
7. 把 `&` 加在固定寄存器约束上（`"=&a"` 常常直接 `impossible constraints`）。
